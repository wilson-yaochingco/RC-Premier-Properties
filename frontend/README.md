# RC Premier Properties — Frontend

Next.js (App Router) + React + TypeScript + Tailwind CSS.

The public MVP includes the home, property catalogue/detail, about, contact, seller and
viewing-request routes. It renders only API-backed property records and shows explicit
empty/error states when inventory or the backend is unavailable.

> Architecture lives in [`/docs`](../docs/README.md), not here.
> See the [architecture overview](../docs/architecture/overview.md).

## Run it

This is an npm workspaces monorepo — install and run from the **repository root**.

```bash
npm install                  # at the repo root
cp .env.example .env.local
npm run dev:frontend         # at the repo root → http://localhost:3000
```

Full setup instructions: [`docs/development/setup.md`](../docs/development/setup.md).

## Layout

```text
src/
├── app/          Routes, layouts, loading and error boundaries
├── components/
│   ├── ui/       Generic primitives — Button, Input, Modal
│   └── layout/   Header, Footer, Navbar, page containers
├── features/     Domain code, one folder per feature
├── hooks/        Globally reusable hooks only
├── lib/          Shared utilities and config helpers
├── services/     API infrastructure spanning multiple features
└── types/        Genuinely global types
```

Feature-specific components, hooks, services and types belong in `features/<name>/`,
not in the global directories. Create a feature folder when that feature begins.

Implemented feature folders are `features/properties/` for API-backed discovery/detail
UI and `features/inquiries/` for the connected public forms. Shared layout and UI
primitives stay under `components/`.

## Public routes

| Route                | Behaviour                                                                |
| -------------------- | ------------------------------------------------------------------------ |
| `/`                  | Editorial home, five-field property search and API-backed featured state |
| `/properties`        | URL-driven filters, sort, results, empty/error states and pagination     |
| `/properties/[slug]` | Published detail, gallery/map fallbacks and inquiry actions              |
| `/about`             | Supplied positioning and geographic focus without fabricated claims      |
| `/contact`           | General or Property-ID-aware inquiry                                     |
| `/sell`              | Seller inquiry; no public document upload                                |
| `/book-viewing`      | Viewing request only; no appointment is confirmed                        |

## Talking to the backend

Import response types and the version prefix from the shared package — never redeclare a
response shape here:

```ts
import { API_PREFIX, type PropertySearchResponse } from "@rc/shared";
import { apiRequest } from "@/services/api-client";

const body = await apiRequest<PropertySearchResponse>(
  `${API_PREFIX}/properties?sort=newest&page=1&limit=9`,
);
```

`apiRequest` normalizes HTTP, network and malformed-JSON failures into
`ApiClientError`. Feature services set their own caching policy and keep endpoint logic
beside the feature.

## Gotchas

- `src/lib/env.ts` is the only place that reads `NEXT_PUBLIC_API_URL` and
  `NEXT_PUBLIC_SITE_URL`. Don't touch `process.env` in components.
- Only `NEXT_PUBLIC_`-prefixed variables reach the browser. Never put a secret in one.
- `.env.local` is read at startup — restart the dev server after changing it.
- `AGENTS.md` and `CLAUDE.md` here are generated by `next dev`. Leave them alone.
- No approved logo, real media, contact details or listings are bundled. Keep the
  labelled fallbacks until those inputs are supplied; see the
  [media replacement guide](../docs/development/media-replacement.md).
- Inquiry submission needs a reachable API and MongoDB. The form does not provide a
  fake success fallback, and inquiry records have no public read route.
